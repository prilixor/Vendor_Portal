Linux Server Operations — How We Continue After Cutover

Internal runbook  ·  3 September 2026  ·  Companion to BlinksMed_Linux_Production.pdf

1. Purpose

Live BlinksMed now runs on Linux. This document is how the team continues day to day: log in, deploy API, deploy UI, check health, backups, and rollback. It is not a new migration plan.

Windows IIS is no longer used for live deploys.

3. How to open the Linux server

There is no RDP. Use AWS Session Manager every time.

  1. AWS Console → region Stockholm (eu-north-1)
  2. EC2 → Instances → blinksmed-linux
  3. Connect → Session Manager → Connect
  4. Type sudo -i so the prompt is root@ip-172-31-18-209

If you are already root, do not type sudo again (it can fail with “permission denied”).

Session Manager does not need the public IP. It still works if someone is confused about RDP.

5. Continue with API code changes

Do this whenever the .NET API changes. Publish must be linux-arm64.

5.1 On the developer PC (PowerShell, folder Prilixor.VendorPortal)

dotnet publish Prilixor.VendorPortal.API\Prilixor.VendorPortal.API.csproj -c Release -r linux-arm64 --self-contained false -o C:\Deploy\publish_api_linux

if (Test-Path C:\Deploy\api-linux.zip) { Remove-Item C:\Deploy\api-linux.zip }
Compress-Archive -Path C:\Deploy\publish_api_linux\* -DestinationPath C:\Deploy\api-linux.zip

Upload C:\Deploy\api-linux.zip to S3 bucket blinksmed-backups → folder migration (overwrite the old zip).

5.1b One time — make the PC JSON the live Linux file

Do this once before full replace. Today’s PC file still has local DB/SMTP/JWT values. Replacing with that would take the API down.

On Linux SSM:

aws s3 cp /var/www/api/appsettings.Production.json s3://blinksmed-backups/migration/appsettings.Production.linux.json

On the PC: S3 → blinksmed-backups → migration → download appsettings.Production.linux.json. Save it as the local gitignored appsettings.Production.json (overwrite the PC copy). Do not commit it. Do not paste it in chat. After that, edit JSON only on that file.

5.2 On Linux SSM (root) — full replace JSON from the zip

Backup live JSON to /root, copy API files, then replace the entire Production JSON from the zip only if DB/JWT/SMTP/keys in the zip match live Linux. If they do not match, the script keeps the live file and prints REFUSED.

systemctl stop blinksmed-api
cp -a /var/www/api/appsettings.Production.json /root/appsettings.Production.json.bak

cd /tmp/migration
aws s3 cp s3://blinksmed-backups/migration/api-linux.zip .
rm -rf /tmp/api-unpack
mkdir -p /tmp/api-unpack
unzip -o api-linux.zip -d /tmp/api-unpack
DLL=$(find /tmp/api-unpack -name 'Prilixor.VendorPortal.API.dll' | head -1)
DIR=$(dirname "$DLL")
cp -a "$DIR"/. /var/www/api/
cp -a /root/appsettings.Production.json.bak /var/www/api/appsettings.Production.json

python3 - <<'PY'
import json, glob, sys
live_path = "/var/www/api/appsettings.Production.json"
cands = glob.glob("/tmp/api-unpack/**/appsettings.Production.json", recursive=True)
if not cands:
    raise SystemExit("zip JSON not found")
zip_cfg = json.load(open(cands[0]))
live = json.load(open(live_path))

def get(d, path):
    cur = d
    for p in path:
        if not isinstance(cur, dict) or p not in cur:
            return None
        cur = cur[p]
    return cur

secret_paths = [
    ("ConnectionStrings",),
    ("JwtOptions", "SigningKey"),
    ("SmtpOptions",),
    ("BootstrapSuperAdmin", "Password"),
    ("Twilio",),
    ("WebPush", "PrivateKey"),
    ("WebPush", "PublicKey"),
    ("Groq", "ApiKey"),
    ("CountryStateCity", "ApiKey"),
]
bad = [".".join(p) for p in secret_paths if get(zip_cfg, p) != get(live, p)]
if bad:
    print("REFUSED full replace — zip secrets do not match live Linux:")
    for name in bad:
        print(" ", name)
    print("Keep live JSON. Run 5.1b (copy Linux JSON to PC), then publish again.")
    sys.exit(1)
json.dump(zip_cfg, open(live_path, "w"), indent=2)
print("FULL REPLACE OK — entire JSON from zip is now live")
print("DispatchOfferTtlMinutes", zip_cfg.get("CustomerPricing", {}).get("DispatchOfferTtlMinutes"))
print("MaxDispatchVendorsPerLine", zip_cfg.get("CustomerPricing", {}).get("MaxDispatchVendorsPerLine"))
print("OrderImageRequest", zip_cfg.get("OrderImageRequest"))
PY

chown -R www-data:www-data /var/www/api
chmod 640 /var/www/api/appsettings.Production.json
systemctl start blinksmed-api
sleep 8
systemctl is-active blinksmed-api
curl -sS -o /dev/null -w "API %{http_code}\n" http://127.0.0.1:5000/api/customers/catalog/categories

Must print FULL REPLACE OK, then active and API 200. If it prints REFUSED, the live JSON was not changed — finish 5.1b first. Rollback: cp -a /root/appsettings.Production.json.bak /var/www/api/appsettings.Production.json then restart the API.

5.3 JSON-only (no API code change)

Edit the PC file that came from 5.1b, publish + upload a new zip, then run 5.2. That replaces the entire live JSON from the zip.

6b. Database SQL (only when a script is required)

PostgreSQL is on the same VM. Four databases: admin_portal_db, vendor_portal_db, customer_portal_db, common_portal_db. Do not restore a dump over live data. Do not paste the DB password into chat.

  1. Confirm which SQL file and which database (read the script header).
  2. On Linux, take a backup first (site stays up).
  3. Copy the .sql to the server (S3 migration/ or paste via SSM).
  4. Apply as local postgres (no app password needed).
  5. Restart the API only if the feature needs it.
# 1) Backup first
/usr/local/bin/blinksmed-backup.sh

# 2) Copy SQL from S3 (example name — use the real file)
mkdir -p /tmp/migration
cd /tmp/migration
aws s3 cp s3://blinksmed-backups/migration/change.sql .

# 3) Apply to the correct database (change the -d name)
sudo -u postgres psql -d vendor_portal_db -v ON_ERROR_STOP=1 -f /tmp/migration/change.sql

# 4) If the API must pick up schema
systemctl restart blinksmed-api
sleep 8
curl -sS -o /dev/null -w "API %{http_code}\n" http://127.0.0.1:5000/api/customers/catalog/categories

Use customer_portal_db, admin_portal_db, or common_portal_db when the script says so. A file that touches two databases must be run twice (once per database), or use the matching apply_*.sh in Database/Scripts/Deploy.

Mobile APKs are not deployed to this server. Customer/Vendor APKs are built on the PC and given to testers/stores.

# API
systemctl restart blinksmed-api
systemctl status blinksmed-api --no-pager
journalctl -u blinksmed-api -n 80 --no-pager

# Nginx
nginx -t
systemctl reload nginx
journalctl -u nginx -n 40 --no-pager

# Database
systemctl status postgresql --no-pager

Do not reboot the VM as a first step.

Reboot only if systemd and Nginx are confirmed healthy and the instance is still broken. After reboot, confirm Elastic IP is still 13.63.29.186.

9. HTTPS certificate

Let’s Encrypt was issued 3 Sep 2026, expires 2 Dec 2026. Ubuntu certbot renews it automatically. To check:

certbot certificates
systemctl list-timers | grep certbot

If HTTPS fails after a long time, do not move the IP. Check that ports 80 and 443 are still open on security group blinksmed-web, then run certbot renew only if a senior confirms.

10. S3 files (photos / documents)

Live files stay in bucket rentalmedicalequipments. The API uses the instance IAM role blinksmed-server-role. Do not add AccessKeyId to appsettings on Linux.

aws s3 ls s3://rentalmedicalequipments/ | head

If this fails, the IAM role is missing or wrong — that is an AWS IAM fix, not a code zip.

14. One-page checklist before every live deploy

  1. You are in region Stockholm.
  2. You will touch blinksmed-linux, not Vendor-Server.
  3. API publish is linux-arm64 (not win-x64).
  4. You backed up appsettings.Production.json to /root before copying API files.
  5. PC Production.json is the Linux copy (5.1b). 5.2 printed FULL REPLACE OK (not REFUSED).
  6. If SQL changed, you ran blinksmed-backup.sh first, then applied SQL to the correct database.
  7. Local curl to port 5000 is 200.
  8. https://vendor.blinksmed.com and API URL still work in the browser.
  9. You did not change Elastic IP, DNS, or security group 80/443.

15. Summary

Continuing on Linux means: Session Manager + S3 zip deploys + systemd API + Nginx static UI. Nightly DB backups already run. Windows is optional rollback only. The live IP and domains stay as they are.
